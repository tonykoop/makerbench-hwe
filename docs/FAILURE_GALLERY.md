# Failure Gallery Workflow

Visible failures are what make a hardware-design benchmark **legible**: a welded
lid, a flipped axis, an impossible cut path, a non-manifold mesh, a clearance
that can never assemble. A score of `2/4` is abstract; a render of the part that
scored it is not. This document defines a small, **public, non-oracle** workflow
for collecting and publishing representative failure artifacts so the
methodology and site can show *why* MakerBench is useful — without ever leaking
the answers.

It deliberately **reuses** the existing site surfaces rather than building a new
page system:

- per-task detail pages (`site/tasks/<id>/`) and per-model pages
  (`site/models/<slug>/`) from [issue #10],
- the methodology blog (`site/blog/`) from [issue #13],
- the archived/versioned leaderboard snapshots (`site/data/archive/`).

The gallery is a thin curation layer on top of those, not a replacement.

[issue #10]: https://github.com/tonykoop/makerbench-hwe/issues/10
[issue #13]: https://github.com/tonykoop/makerbench-hwe/issues/13

## The hard rule: candidate artifacts and public diagnostics only

A gallery example may only contain things a member of the public could already
see or reproduce from a submitted run:

- a **candidate** (model-produced) artifact, or a **synthetic** illustration a
  maintainer drew by hand to demonstrate a failure mode;
- public grade output — *which* levels failed and the public, parameter-derived
  reason string the grader emits;
- render/section images captured from a candidate artifact (perception track) or
  hand-made placeholders.

A gallery example may **never** contain, reference, or be derived from:

- oracle geometry (`private/oracles/**`, any `oracle.scad`);
- private threshold values, exact answer dimensions, or held-out fixture
  internals;
- official held-out seeds or any `private/` path;
- local absolute paths (`/home/...`, `/mnt/...`, `C:\Users\...`).

These rules are enforced mechanically — see [Validation](#validation). The
guiding principle is the same one the rest of the benchmark uses: **publishing a
failure must never teach anyone the answer.**

## Bundle format

Curated examples live in `site/data/failure_gallery.json`. It is **hand-authored
and committed** — unlike `data/leaderboard.json`, it is *not* generated by
`site/build_data.py`, and `build_data.py` never reads or rewrites it. The site
consumes it directly (a small vanilla-JS fetch on the gallery page), so no new
framework or build step is introduced.

Top level:

```jsonc
{
  "version": "0.1.0",
  "_doc": "Curated PUBLIC failure examples ... synthetic/candidate only, never oracle.",
  "examples": [ /* Example objects */ ]
}
```

Each **Example** object:

| Field | Type | Meaning |
|-------|------|---------|
| `id` | string (slug) | Stable unique id, e.g. `welded-lid-enclosure-01`. |
| `task_family` | string | A **public** registry family id (`tasks/registry.json`). Used to cross-link `tasks/<id>/`. |
| `track` | `"blind"` \| `"perception"` | Which track the failure illustrates. |
| `title` | string | Short human title, e.g. "Welded lid: base and lid fused into one body". |
| `failure_kind` | string (slug) | Canonical kind: `welded_lid`, `flipped_axis`, `impossible_clearance`, `non_manifold`, `bad_flat_pattern`, `impossible_cut_path`, … |
| `source` | object | `{ "type": "synthetic"\|"candidate_artifact"\|"public_fixture", "ref": <public path or description>, "public": true }`. |
| `artifacts` | array | `{ "role": "render"\|"section"\|"diagram", "label": str, "path": <public site-relative path> }`. Placeholders allowed if labeled. |
| `failed_levels` | array | `{ "level": 1–4, "name": str, "why": <public reason> }` — which grade levels failed and why, in public language. |
| `summary` | string | One-line takeaway. |
| `explanation` | string | 2–4 sentences a non-expert can follow. Public-safe. |
| `provenance` | object | `{ "synthetic": bool, "captured_from": str\|null, "notes": str }`. |
| `privacy` | object | `{ "uses_oracle": false, "reviewed": true, "notes": str }`. `uses_oracle` must be `false`. |
| `related` | object | `{ "task_page": "tasks/<id>/", "model_page": "models/<slug>/"\|null }`. |

The four grade levels referenced in `failed_levels` are the public ladder
(1 structural, 2 geometric, 3 physics, 4 DFM) already documented in the
methodology post and `site/build_data.py`.

## How a maintainer selects an example safely

1. **Start from a candidate, not the oracle.** Pick a submitted/synthetic
   artifact that *visibly* fails. Never open `private/oracles/**` to build an
   example, and never quote a private threshold — describe the failure
   qualitatively ("walls thinner than the printable minimum"), not numerically
   against the held-out gate.
2. **Capture only public diagnostics.** Use the grader's public level results and
   reason strings, and renders taken from the candidate artifact. If you have no
   real capture yet, use a labeled **synthetic placeholder** image and set
   `provenance.synthetic = true`.
3. **Strip paths.** Image/source paths must be **site-relative and public**
   (`assets/failure-gallery/...`). No absolute paths, no `private/`, no
   `runs/...` machine paths.
4. **Write it for a stranger.** The `explanation` should make the failure obvious
   to someone who has never read the rubric, without revealing the target
   geometry.
5. **Mark provenance honestly.** Synthetic vs. captured, and whether the render
   is a placeholder. Set `privacy.reviewed = true` only after a second read for
   leakage.
6. **Validate.** Run the validator (below). It blocks the obvious leaks and
   format drift.

## How future examples get added

Append an Example object to `examples` in `site/data/failure_gallery.json`,
drop any public render under `site/assets/failure-gallery/`, run the validator,
and open a PR. No regeneration step is required; the gallery page picks up the
new entry on next load. Real captured renders can replace synthetic placeholders
over time — just flip `provenance.synthetic`/the placeholder label and swap the
image path.

## Where it surfaces

- **`site/blog/failure-gallery.html`** — a lightweight, launch-facing page that
  fetches `data/failure_gallery.json` and renders the examples as cards, with a
  prominent banner that the current set is synthetic/placeholder. It cross-links
  the methodology post and the per-task detail pages.
- **`site/blog/index.html`** — a post card linking to the gallery.

This keeps the gallery consistent with the existing static, deterministic site
and avoids duplicating the detail-page system.

---

## Validation

`site/validate_failure_gallery.py` checks the bundle against this format and
against the privacy rules (allowed public family ids from `tasks/registry.json`,
allowed tracks/roles, `uses_oracle == false`, public site-relative paths, and a
global scan for forbidden substrings like `oracle.scad`, `private/`, and
absolute paths). Run it directly, or via the focused test
`tests/test_failure_gallery.py`:

```bash
python site/validate_failure_gallery.py
python -m pytest tests/test_failure_gallery.py -q
```

A non-zero exit (or failing test) means an example is malformed or risks leaking
non-public content — fix it before merging.
