# MakerBench Distribution Packet

This packet turns MakerBench-HWE into something contributors can discover,
share, and rally around without exposing answers. It is public by design: no
held-out seeds, oracle geometry, source artifacts, or private thresholds belong
here.

## Badge Endpoint

Every leaderboard row gets a static shields.io endpoint payload generated by:

```bash
python site/build_data.py
```

The generated endpoint lives at:

```text
site/data/badges/<badge_slug>.json
```

The hosted badge URL is:

```text
https://img.shields.io/endpoint?url=https%3A%2F%2Ftonykoop.github.io%2Fmakerbench-hwe%2Fdata%2Fbadges%2F<badge_slug>.json
```

Use the Markdown emitted in `site/data/badges/index.json` for contributor
READMEs. It links the badge back to the generated per-model share page:

```md
[![Built with MakerBench](https://img.shields.io/endpoint?url=https%3A%2F%2Ftonykoop.github.io%2Fmakerbench-hwe%2Fdata%2Fbadges%2F<badge_slug>.json)](https://tonykoop.github.io/makerbench-hwe/models/<badge_slug>/)
```

The badge text is intentionally normalized to `NN/100 blind` so it reads well in
GitHub READMEs while still deriving from the canonical 0-4 MakerBench blind-track
score. A missing blind score renders as `blind score pending`.

## MCP Registry Submission

Goal: make "CAD", "3D", "hardware automation", "Blender MCP", and "maker
benchmark" searches find MakerBench early.

### Submission Targets

- Official MCP server registry or catalog when the Blender MCP integration is
  eligible for public listing.
- `awesome-mcp` and adjacent MCP index repos.
- Blender MCP project directories or examples pages, if they accept downstream
  workflow listings.
- Maker or CAD automation lists that accept benchmark/tool entries.


### Submission Checklist

- [ ] Link to the public repository, not private oracle or submission archives.
- [ ] Link to the public leaderboard and workflow docs.
- [ ] Include the canary and data-policy language by reference, not by copying
      large policy blocks.
- [ ] State that Blender MCP is one workflow-track stack, not a required
      dependency for the core leaderboard.
- [ ] Confirm no private source artifacts, gold geometry, held-out seeds, or
      official thresholds are included in the registry PR or issue.
- [ ] After acceptance, add the registry link to this section.

## Code-First CAD Outreach

Use tailored, low-friction posts. Each outreach seed should give a community a
reason to try its native stack while making the integrity boundary obvious.

### CadQuery

- Hook: "Can CadQuery agents beat text-to-OpenSCAD on manufacturable assemblies?"
- Seed: invite a `brep-build123d` or future CadQuery-compatible STEP run with a
  metadata-only public result PR.
- Ask: request feedback on topology diagnostics and STEP handoff fields.

### build123d

- Hook: "MakerBench's B-rep profile starts with build123d because it is Pythonic,
  headless, and close to OCCT."
- Seed: point to `docs/BREP_PROFILE.md` and the runnable proof-of-life task.
- Ask: invite idiomatic build123d examples that improve agent prompts without
  exposing solved benchmark artifacts.

### CQ-Editor

- Hook: "Interactive code-CAD review could be a human-in-the-loop workflow track."
- Seed: ask for a clean way to log edits, screenshots, and exported STEP files
  into a WorkflowManifest.
- Ask: find maintainers willing to validate a CQ-Editor workflow packet.

### OpenSCAD

- Hook: "MakerBench's core profile is deliberately OpenSCAD-first: transparent,
  deterministic, diffable, and CI-runnable."
- Seed: invite OpenSCAD users to propose new parametric task families with public
  graders and private gold answers.
- Ask: look for edge cases where the current harness or render path makes
  idiomatic OpenSCAD harder than it should be.

## Community Launch Checklist

The community layer should send energy back into quarterly challenges, not split
the canonical record away from the repo.

- [ ] Create one canonical community home, such as a GitHub Discussion category
      or an `r/HardwareAI` style space.
- [ ] Pin the integrity rules: no oracle leaks, no source artifacts in public
      result PRs, no self-verification-status upgrades.
- [ ] Create starter flairs: `[Workflow Stack]`, `[Prompt/Trace]`,
      `[Blender MCP]`, `[Moonshot Entry]`, `[Maker Log]`.
- [ ] Launch a Prompt-to-STEP exchange where every post shows public geometry
      renders or share-page links, never hidden answers.
- [ ] Pin a quarterly challenge thread that links to `docs/CHALLENGE_SPEC.md`.
- [ ] Require posts about scores to include the `Built with MakerBench` badge or
      a link to the model share page.
- [ ] Route suspected contamination, memorization, or leaked artifacts to
      `docs/CONTAMINATION_RESPONSE.md` before discussion spreads.
- [ ] Close each challenge window with a public recap and a private-oracle
      rotation check.

## Done Definition

This distribution packet is complete for issue #99 when:

- badge endpoint JSON emits `Built with MakerBench: NN/100 blind`;
- `site/data/badges/index.json` contains copy-paste Markdown for each row;
- the registry entry draft and submission checklist are public and safe;
- outreach prompts exist for CadQuery, build123d, CQ-Editor, and OpenSCAD;
- the community launch checklist names flairs, Prompt-to-STEP, quarterly
  challenge routing, and contamination handling.
